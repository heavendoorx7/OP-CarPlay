# 安装与使用

## 首次配置

公开 APK 不内置认证材料。安装之后，先配置认证与热点，再连接 iPhone。

1. 从 Releases 下载 APK，使用你已有、可用的安装途径。GitHub 不提供离线安装包、安装 command 或捆绑 ADB。
2. 确保车机原生热点已开启。OP 的 Wi-Fi 会话选择原生/手动热点，填写实际 SSID、密码与安全类型。不要照抄其他车的设置。
3. 选择认证方式。本地文件方式需要配套的 DER PKCS#7 证书 `.p7b` 和未加密 DER PKCS#8 私钥 `.pk8`；使用你有权使用的文件。也保留上游硬件与远程认证配置。
4. 将 iPhone 与车机蓝牙配对，保存设置并连接。首次使用按系统提示授予所需权限。

“使用内置认证文件”只是个人构建可选能力；公开包没有对应文件，不能靠这个按钮生成认证材料。远程方式需要你自己配置服务，项目没有为你开通服务器。

## 显示与设置

- **分屏：** 使用原车分屏入口，将 OP 放在右侧；原车导航、状态栏和 Dock 按原车布局显示。
- **带系统栏全屏：** 主屏 OP 避让原车上、下、左侧界面。
- **完全全屏：** 隐藏原车系统栏与 Dock。
- 通过画面上的小图标切换；默认启动模式在设置中选择，初始为完全全屏。
- 在 CarPlay 区域内，五指张开放下再向内收拢，或三指下滑，呼出设置。
- 修改后保存。窗口尺寸变化仍可能引起重新协商/重连，不是无缝切换。

## 两种授权到底授权什么

### 原生热点

“自动开启原车热点”默认关闭。启用前需要原车允许本应用使用相应设置操作。应用的授权命令限定为：

```bash
adb shell cmd appops set --user 0 com.shilapi.xcertplay.p7 WRITE_SETTINGS allow
adb shell cmd appops get --user 0 com.shilapi.xcertplay.p7 WRITE_SETTINGS
```

可以在 OP 内选择：

- **本机 ADB：** 车机的网络 ADB 必须已经开启，并允许 OP 自己的连接。电脑曾被允许，不代表 OP 的 ADB 身份也已被允许。
- **Shizuku：** Shizuku 必须已经运行，再允许 OP。仅安装 Shizuku 不等于它已运行；重启后可能需要重新启动。

两种入口执行同一个、只针对 OP 的授权；都不能开启原本关闭的 ADB，也不能绕过系统授权。后续热点启动使用原车服务和本应用身份。授权状态能否保留、开机/唤醒能否触发，依固件而定。

自动热点复用原车配置，不更换 SSID/密码、不强制改频段、不自动降级成 LocalOnlyHotspot。车机原生热点是 5 GHz 时复用它；若系统配置为 2.4 GHz，本功能不会凭空变成 5 GHz。

### 仪表

进入“仪表导航”，通过 **本机 ADB 启动** 或 **通过 Shizuku 启动** 运行固定用途的 shell 辅助进程。这与热点的 `WRITE_SETTINGS` 授权不是同一件事；只给热点授权不足以启动仪表输出。

**仪表盘导航目前仅测试了高德地图，其他地图应用未验证。** 让原车仪表显示导航卡片，连接 CarPlay 并在高德地图中启用导航。状态可能依次为：

- 等待 CarPlay：主连接尚未就绪。
- 等待 iPhone 独立地图：主屏已连，但第二路尚未收到有效画面。
- 等待原车导航卡片：仪表没有请求地图区域。
- 通道运行中：已向原车接口提交有效画面，不等于所有视觉效果已被人眼确认。

充电等原车页面可能覆盖导航卡片。不要为了显示 OP 去修改车辆充电或仪表状态。

## 原车蓝色车道条

“OP 投放时隐藏原车车道提示”默认开启，可关闭。

- 投放开始立即提交 lane 清除，之后定期维持。
- 退出、断开或关闭该选项后停止清除。
- 有本轮原车车道缓存时尝试恢复；无缓存时等待原车下一次车道更新，可能不会立刻重现旧蓝条。
- 原车地图画面的重建是另一条恢复流程，不要把地图恢复和蓝条恢复混为一谈。

第二路地图范围、3D、车道级内容由地图应用决定。应用内缩放命令可能不被所有地图应用支持。

## 更新与退出

正式维护者签名的同包更新可保留设置；自己重新签名的 APK 无法直接覆盖不同签名的安装。

公开包替换个人内置文件版后，原先指向内置 Provider 的认证选择可能失效，需要重新选自己的认证文件。不要为解决签名或版本问题直接卸载而丢失配置。

退出使用 OP 设置中的“退出应用”。若原车小地图未恢复，请停车后记录 OP 状态并报告，不要在行驶中操作。较低 `versionCode` 通常不能直接覆盖降级。
